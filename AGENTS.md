# Working rules: Field Shift Banyumas

This repo is built by **Bintang** ([@bintangfabian](https://github.com/bintangfabian)) and **Haikal** ([@HaikalFaruq](https://github.com/HaikalFaruq)) for the NASA Space Apps Challenge 2026, often with help from AI agents. These rules apply to both of us and to any agent we use.

They follow the Wingman Clutch house rules, with two additions for NASA Space Apps: everything is written in English, and AI use is disclosed inside the project (section 2).

## 1. No AI attribution in git history

Commits, PRs, issues and comments are recorded under the person who ran them. Never add AI attribution there in any form:

- Trailers such as `Co-Authored-By: Claude <noreply@anthropic.com>`, `Claude-Session: …` or `Assisted-by: …`, and similar trailers from other agents (Codex, Copilot, Cursor, Gemini, Aider, Devin, Jules, Amp, Warp, and so on).
- Footers such as `🤖 Generated with Claude Code` or `Generated by Copilot`, and agent session links.
- An AI agent or bot as author or committer, such as `claude[bot]`, `Copilot`, `Cursor Agent`, `devin-ai-integration[bot]`, or a name ending in `(aider)`. Always commit with your own git identity.

If your agent adds attribution automatically, turn it off in its settings. For Claude Code it is already off through `.claude/settings.json` in this repo.

The rule is checked in layers, so a violation stops before it reaches `main`:

| Layer | What it checks | When |
| --- | --- | --- |
| `.githooks/commit-msg` | The commit message | Every `git commit` |
| `.githooks/pre-push` | Author, committer and message of every pushed commit | Every `git push` |
| Workflow `No AI attribution` | Same as pre-push, plus the PR title and description | Every PR and every push to `main` |

The hooks turn on automatically after `npm install` (the `prepare` script). If they are off, turn them on once per clone:

```sh
git config core.hooksPath .githooks
```

If a check fails, fix the commit. Don't skip the hooks with `--no-verify`, because CI rejects the commit anyway.

| Case | Command |
| --- | --- |
| Last commit message | `git commit --amend`, then remove the attribution |
| Last commit author | `git commit --amend --reset-author --no-edit` |
| Older commits | `git rebase -i origin/main`, mark them `reword` or `edit`, then `git push --force-with-lease` to your feature branch, never to `main` |

All patterns are in `scripts/check-no-ai.sh`, with examples in `scripts/test-check-no-ai.sh`. These two scripts are copied unchanged from our other repos, so their comments are in Indonesian.

## 2. AI disclosure inside the project (NASA Space Apps rule)

This is separate from section 1. The NASA Space Apps [Project Submission Guide](https://www.spaceappschallenge.org/resources/project-submission-guide/) requires that AI ("Super Intelligence", SI) use be shown in the project itself, where judges can see it:

- **Code and data:** acknowledge AI generation in descriptive text and in metadata. In this repo that means the README section [Use of AI](README.md#use-of-ai), a one-line `AI-assisted` header at the top of every AI-assisted file, and a `processing` field in generated data files.
- **Images and video** made with AI need a visible watermark. **Audio** needs a note in descriptive text and metadata.
- AI content must not use, contain or modify NASA logos, flags, mission identifiers or other NASA branding.
- AI must not be used to come up with our solution idea. The idea, the users and the features come from us. AI helps with research, data processing, code and writing.

Keep these markers when you edit a file. When an agent writes a new file, it adds the header.

## 4. Commit and PR messages

Anyone reading them should understand what changed and be able to continue from there.

**Commits:** Conventional Commits in **English** (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `ci:`). NASA requires English in everything the judges may open, and that includes this repo. Keep the title to 72 characters or less. The body explains what changed and why.

**PRs:** the description uses these sections.

```markdown
## What changed
## Why
## Checked
## Next
```

**Next** lists the next steps, open items, or decisions the partner needs to make. Never leave it empty.

## 5. Workflow

Issue → branch (`feat/…`, `fix/…`, `docs/…`) → PR → merge, one topic per PR. Don't push directly to `main`.

At the start of every session, including AI agent sessions:

1. Sync first: `git switch main && git pull`.
2. Check that the hooks are on: `git config core.hooksPath` must print `.githooks` (section 1).
3. Read the roadmap and its comments: `gh issue view 1 --comments`. The last comment holds the next step from the partner.
4. Take one unchecked item and work on it through the flow above.
5. After the PR is merged, tick the item in #1.

**Deadline:** the Space Apps Project page must be submitted by **Sunday 15 November 2026, 23:59 WIB**. Anything saved after that is not eligible.

Before you push, make sure `npm run build` passes. CI runs it on every PR (workflows `CI` and `No AI attribution`), and `main` deploys to GitHub Pages.

## 7. Architecture

```
src/
  App.tsx       layout: header, map, side panel (desktop) or bottom sheet (phone)
  components/   map, climate panel and chart, placeholder card, attribution footer
  lib/          data loading, climatology helper, types, media query hook
scripts/        data download scripts and the AI-attribution check
public/data/    generated data that ships with the app (works offline)
.githooks/      commit-msg and pre-push hooks
```

- The app makes no runtime API calls except OpenStreetMap tiles. External data is downloaded at build time by the scripts in `scripts/` and stored in `public/data/`.
- Load data only through `src/lib/data.ts`, which respects the Vite base path (`BASE_PATH`) used on GitHub Pages.
- The UI is in English and mobile-first. Check it at 320 px and 390 px wide.

### Architecture diagram

The interactive diagram ([`public/architecture.html`](public/architecture.html), live at `…/field-shift-banyumas/architecture.html`) is made with [Archify](https://github.com/tt-a1i/archify) v3.2.0 from `docs/architecture.archify.json`. Every box links to lines of code at the commit in `meta.repository.revision`. When the architecture changes:

1. Update the JSON, including the revision and the cited line numbers. Cite committed code: the links point at that revision.
2. Clone Archify outside the repo, then run `node <archify>/archify/bin/archify.mjs finalize architecture docs/architecture.archify.json .archify/architecture.html --repo-root . --quality showcase --json`. The `.archify/` folder is ignored.
3. Copy `.archify/architecture.html` to `public/architecture.html`.
4. Export a PNG in light and in dark mode from the diagram's **Export** button, then save each as a 2400 px WebP: `cwebp -q 95 -resize 2400 0 <png> -o docs/images/architecture-light.webp` (same for `architecture-dark.webp`).

The service worker keeps this page out of the offline cache and never answers its URL with the app shell (`globIgnores` and `navigateFallbackDenylist` in `vite.config.ts`).

## 8. Data and licenses

- Every data source used in the app goes in the README table **Data sources and licenses**, and later in the Space Apps form (**NASA Data** or **Space Agency Partner & Other Data**). That includes libraries, code and images, even open-source ones.
- Keep the required credits: the NASA POWER acknowledgment, the geoBoundaries citation (CC BY 3.0 IGO), and © OpenStreetMap contributors (ODbL).

## 9. Security

- No server, accounts or secrets in the frontend.
- Earthdata Login credentials stay in each developer's `~/.netrc`, never in this repo.
- External links use `target="_blank"` with `rel="noopener noreferrer"`.
